## 一、设计决策（用户确认）

| 维度 | 决策 |
|------|------|
| 登录方式 | 邮箱+密码（自建，scrypt 哈希，零外部依赖） |
| 可见性 | 默认公开，每首诗可切换私密（私密仅本人可见） |
| 旧数据归属 | 预留管理员邮箱 `ADMIN_EMAIL`，用该邮箱注册时自动继承全部历史数据 |

## 二、改动清单

### 服务端
| 文件 | 说明 |
|------|------|
| `src/lib/user.ts`（新增） | 密码哈希（scrypt，salt:hash）、用户 CRUD（users:byEmail/byId）、会话（sessions:{token}，TTL 30 天）、requireUser/optionalUser、可见性 isPoemVisible、权限 canModifyPoem/Collection、claimLegacy（旧数据继承，幂等 meta:legacyClaimed）、isAdminEmail |
| `api/auth/register`（新增） | 注册（邮箱格式/密码≥6位/昵称/邮箱查重 409）；管理员邮箱自动 claimLegacy；返回 token+user |
| `api/auth/login`（新增） | 登录校验 → token+user（401 错误凭据） |
| `api/auth/me`（新增） | 当前用户（401 未登录） |
| `api/auth/logout`（新增） | 删除会话 |
| `api/poems` | GET 按可见性过滤（public+本人 private，剔除软删除）；POST 需登录，自动 ownerId/ownerName/visibility |
| `api/poem/[id]` | GET 可见性校验（private 非本人 404）；PUT/DELETE 需登录+本人（403），防篡改 ownerId/ownerName/id |
| `api/poems/[id]` PATCH | 需登录+本人，仅安全字段 |
| `api/poems/batch-tags` | 需登录，仅处理本人的诗 |
| `api/collection` | POST 需登录+ownerId |
| `api/collection/[id]` DELETE | 需登录+本人（403） |
| `src/lib/kv.ts` | RedisLike 增加 `del` |

## 四、部署注意（生产上线步骤）

1. Vercel 配置 `ADMIN_EMAIL`（你的邮箱），**先部署再注册该邮箱** → 自动继承现有全部诗词/藏。
2. 若未配置 ADMIN_EMAIL 就有人抢先注册，旧数据将无归属（保持公开可见但无人可管理）——**请在上线前配置**。
3. `POEM_PASSWORD` 已退役（写操作鉴权迁移到账号体系），可保留或删除。
4. 旧 localStorage 密码缓存无影响（已忽略）。
