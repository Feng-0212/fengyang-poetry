## 已完成

### ① 节气表数据错误（10月1-22日错显示「立春」）✅

`src/lib/solarterms.ts` 的 `SOLAR_TERM_BY_DATE` 存在 3 条 `end < start` 的占位记录（`1001-907`、`1008-909`、`1010-922`），导致 10 月 1-22 日在 `getSolarTerm()` 中永不匹配、回退到默认「立春」；8 月另存 2 条同类垃圾占位（`801-706`、`707-708`）。

**修复**：按 `SOLAR_TERMS_META.dateRange` 的节气起始日程序化生成全年连续区间表（25 条），每个节气自起始日延续至下一节气起始日的前一天，跨年区间（1月1-4日）归冬至。

**验证**（Node 脚本）：
- 全年 365 个合法日期 100% 覆盖，无空洞、无重叠
- 顺序连续性通过（立春→大寒 循环，允许同节气延续）
- 回归：10/1→秋分、10/8→寒露、10/22→寒露、10/23→霜降、8/7→立秋、8/22→处暑 ✓

### ② 写作热力图永远为空 ✅

`src/app/stats/page.tsx` 用 `typeof p.createdAt === "string"` 判断日期键，而 `createdAt` 全链路为 number 时间戳，恒不匹配 → 热力图 365 天全 0；且原实现用 `toISOString()`（UTC）存在时区偏移。

**修复**：改用 `Date` 对象本地时区生成 `YYYY-MM-DD` 键；number 时间戳直接转换，兼容旧 string 数据（`new Date(ts).getTime()`）。

**验证**：Node 模拟 `createdAt=1723000000000` → 正确生成本地日期键并计数 ✓

### ③ AI 配图回退图池文件缺失（全 404）✅

`FALLBACK_IMAGES` 引用 `/images/fallback/*.jpg`，但 `public/images/` 目录不存在，AI 生图失败时返回 404 破图。

**修复**：
- 新增 `scripts/gen-fallback-images.mjs`：生成 14 张水墨风 SVG（春/夏/秋/冬 × 3 + default × 2），含季节色渐变、远山、月亮/花瓣/雪/红叶元素与印章装饰
- 生成 `public/images/fallback/*.svg`（14 张）入库
- `src/app/api/ai/image/route.ts` 路径更新为 `.svg`

**验证**：`ls public/images/fallback/` 14 张 SVG 全部存在 ✓

### ④ 画廊布局日期显示「undefined/undefined」✅

`src/app/yuan/[slug]/page.tsx` 的 GalleryLayout 用 `formatDate(createdAt).split("-")[1]` 取月/日，而 `formatDate` 返回中文格式「2026年8月7日」（无连字符）→ split 结果恒为 undefined。

**修复**：改用 `new Date(createdAt).getMonth()+1 / getDate()` 直接取月/日。

**验证**：Node 验证 `formatDate` 无 `-`，新逻辑输出正确月/日 ✓

### ⑤ 写诗/改诗页连续弹两次密码框 ✅

`/yuan/[slug]/write` 与 `/poem/[id]/edit` 的 `handleSubmit` 内部已调用 `requirePassword`，保存按钮 `onClick` 又包了一层 `requirePassword(handleSubmit)` → 验证通过后再次弹窗。

**修复**：按钮改为直接 `onClick={handleSubmit}`（保留 handleSubmit 内部唯一的密码门）。

**验证**：代码走查确认弹窗路径唯一 ✓

## 技术细节

- 节气表生成逻辑：`start = 节气起始日`，`end = 下一节气起始日前一天`；冬至区间跨年（1221-1231 + 101-104）。生成与验证脚本可直接复现，避免手写区间再引入脏数据。
- SVG 回退图：与站点季节色（solarterms.ts getSeasonColors）呼应的浅色水墨风，`<img>` 直接渲染，无外部依赖。
