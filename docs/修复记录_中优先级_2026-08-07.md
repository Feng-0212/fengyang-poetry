## 已完成

### ⑥ 生产依赖混入 @vegamo/deepcode-cli ✅

`package.json` dependencies 中存在未提交的 CLI 开发工具依赖。

**修复**：从 dependencies 移除，`npm install` 同步 `package-lock.json`（grep 确认 lock 中已无 deepcode-cli），node_modules 同步清理。

**验证**：`git diff package.json` 干净，lock 无 deepcode-cli ✓

### ⑦ 语义搜索路由 Redis.fromEnv() 无环境变量即崩溃 ✅

`src/app/api/ai/search/route.ts` 在模块顶层 `const redis = Redis.fromEnv()`，本地开发（无 KV 环境变量）时模块加载即抛错，整个路由 500。

**修复**：改用 `lib/kv.getKv()`（含内存回退），在请求处理内读取 `poems:all`；无 Redis 时优雅降级为空列表并返回「暂无诗词数据」，不再崩溃。

### ⑧ 双数据源不同步：seasons 页读 IndexedDB 本地而非云端 ✅

`/yuan/sishi-moyuan/seasons` 节气诗库此前直接读 IndexedDB 本地数据（`db.getPoemsBySolarTerm` 等），与云端不同步；另清理 db.ts 死代码。

**修复**：
- seasons 页改用 `useAllPoems()`（云端优先、IndexedDB 降级），客户端过滤藏/季节/节气，与其他页面数据源一致
- `src/lib/db.ts` 删除无引用死函数：`getAllPoems`、`getPoemsBySolarTerm`、`getPoemsBySeason`、`exportAllData`、`importData`
- `src/app/settings/page.tsx` 移除 `importData` 死 import

**验证**：grep 确认以上函数/import 无残留引用 ✓

### ⑨ 收藏计数语义混乱（favoriteCount 被当多人收藏）✅

`favoriteCount` 实为单用户收藏的冗余计数，但 tags 页按它做「收藏热榜」，语义误导。

**修复**：
- tags 页热门榜改为「我的收藏」：按 `isFavorite` 过滤（保留 favoriteCount 排序兼容旧数据），文案同步更新
- `types/poem.ts` 注释澄清 favoriteCount 为「与 isFavorite 同步的冗余计数，不代表多人收藏数」

### ⑩ 回收站 30 天自动清理未实现 ✅

软删除诗词永不过期，页面标注「待实现」。

**修复**：`GET /api/poems` 增加惰性清理（`lazyPurgeTrash`）——超过 30 天的软删除记录物理清除；每天最多执行一次（Redis 键 `trash:lastPurge` 记时，TTL 2 天）；无 Redis 时跳过；失败不影响主流程。trash 页文案去掉「（待实现）」。

### ⑪ AI 标签池三处不一致（18/24/12）✅

单首 AI 打标签（18 池）、批量打标签（24 池）、TagInput 快捷标签（12 个）各维护一份标签列表，推荐口径不一。

**修复**：新增 `src/lib/tags.ts` 统一 24 标签池：
- `TAG_POOL`（24 个）→ `/api/ai/tags` 与 `/api/poems/batch-tags` 共用
- `SUGGESTED_TAGS`（前 12 个）→ TagInput 快捷标签

**验证**：grep 确认三处均 import 共享池，无本地重复定义 ✓

### ⑫ 语义搜索结果被丢弃（仅给文本结果加权）✅

`useSearch.search()` 仅在文本结果上加权，语义搜索命中的诗若不在文本结果中则完全不显示。

**修复**：语义命中且文本未命中的诗以「semantic」类型并入结果并置顶（score 150），再与加权后的文本结果合并排序、截断 50 条。

### ⑬ 密码安全：fallback 硬编码进 bundle、服务端认 NEXT_PUBLIC 密码 ✅

前端 `PasswordGate` 硬编码 fallback 密码 `zsklj` 打进 bundle；服务端同时认 `NEXT_PUBLIC_POEM_PASSWORD`（公开可读）。

**修复**：
- `PasswordGate`：移除硬编码密码，前端仅收集输入 → `setStoredPassword` → 执行 action；校验完全交由服务端
- `src/lib/auth.ts` `checkPassword`：只认非公开环境变量 `POEM_PASSWORD`，不再接受 NEXT_PUBLIC 密码
- `src/lib/api.ts`：401 时 `clearStoredPassword()`，清除错误密码

**⚠️ 部署注意**：服务端不再接受 NEXT_PUBLIC 密码。若生产当前仅配置了 `NEXT_PUBLIC_POEM_PASSWORD`，上线后写操作将全部 401，**必须在部署前配置 `POEM_PASSWORD`**。

## 技术细节

- 惰性清理使用「GET 读接口顺带清理」而非独立 cron：不依赖 Vercel Cron 配置，生产/本地均生效；用 `trash:lastPurge` 节流避免高频写。
- 语义并入的实现将「语义独立命中」score 设为 150，高于文本最高 100 分，保证 AI 推荐结果优先展示。
- 密码安全采用「前端零密码知识 + 服务端单一权威校验」：即使前端 bundle 被完全反编译，也拿不到有效密码。
